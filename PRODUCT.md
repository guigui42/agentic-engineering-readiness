# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Engineering leaders, platform teams, security leaders, and technical
practitioners preparing to expand AI agent participation in software delivery.
They use the site before or during a readiness workshop to assess the system
around agent work and agree on practical next steps.

## Product Purpose

Turn GitHub's Agentic Engineering System into a public, customer-shareable
self-assessment. Success means a visitor can place their current operating
model in the AES Stock-Adoption matrix, understand the evidence behind that
placement, and leave with a prioritized GitHub preparation plan.

## Positioning

The site evaluates the surrounding engineering system rather than grading an
agent or counting product adoption. It connects governance and shared knowledge
to the current range of agent participation, then maps the gaps to concrete,
publicly documented GitHub practices.

## Operating Context

- Used as a self-guided assessment or facilitated workshop.
- Answers and generated results stay in the visitor's browser.
- Results can be copied as Markdown into an issue, planning document, or
  workshop record.
- The canonical public deployment is GitHub Pages.
- Public GitHub AES, Well-Architected, and Docs pages are the publication
  sources. Internal Seismic material is research input only.

## Capabilities and Constraints

- Four-state evidence scale: not in place, partially in place, established,
  measured and improving.
- Separate scores for governance, shared knowledge, agent adoption, and
  customer value signals.
- Primary classification uses the four AES Stock-Adoption quadrants.
- Missing operating preconditions become blockers or constraints, not score
  boosters.
- No backend and no collection of assessment answers.
- Anonymous analytics, when configured, never include answers, scores,
  quadrant placement, or exported plan text.
- The assessment is directional guidance, not a certification or universal
  delegation threshold.

## Brand Commitments

- Product name: Agentic Engineering readiness.
- Stay recognizably related to
  `guigui42/secure-copilot-agents`: GitHub-native interaction patterns,
  technical clarity, light and dark themes, and source-forward content.
- The new site needs a distinct AES visual emphasis around stocks, activity
  loops, participation, and the Stock-Adoption matrix.

## Evidence on Hand

- GitHub AES public framework:
  https://github.com/resources/insights/agentic-engineering-system
- GitHub Well-Architected AES recommendation:
  https://learn.github.com/well-architected/governance/recommendations/agentic-engineering-system-on-github
- Reference implementation:
  https://github.com/guigui42/secure-copilot-agents
- No customer testimonials, benchmarks, certification claims, or proprietary
  assessment thresholds are available and none should be invented.

## Product Principles

- Assess the system, not only the agent.
- Make evidence and scoring transparent.
- Prioritize foundations before expansion.
- Connect delivery speed to customer value and quality.
- Keep private assessment data local.

## Accessibility & Inclusion

The public site must support keyboard navigation, reduced motion, responsive
mobile and desktop layouts, and automated WCAG A and AA checks.
